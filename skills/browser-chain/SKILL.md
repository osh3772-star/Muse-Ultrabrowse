# browser-chain — 브라우저 작업 라우팅 규약 (폴백 체인)

메타(이 인스턴스)가 브라우저 작업을 받을 때 따르는 규약. 한 도구에서 막히면
같은 지시를 다시 설명받지 않고 다음 레인으로 자동 전환해 끝까지 수행하고,
결과와 총 시간만 보고한다. 설계 원본: `~/workspace/browser-chain/CHAIN-DESIGN.md`
(2026-11-20 사용자 승인, 미결정 2건은 기본값 확정: L1 먼저·시간 예산 5분).

적용 범위: 이 인스턴스의 모든 브라우저 작업. 운영 뮤즈의 부동산 워크플로는 별개.

## 기본 구동 방식 — 원샷 실행 (2026-11-21 사용자 결정)

모든 레인의 기본은 **원샷**이다: 작업 1건 = 스크립트 1개 작성 → 호출 1회로 완결.
단계마다 스냅샷을 보고 판단한 뒤 다음 호출을 거는 반복(호출당 고정 비용과
판단 왕복이 누적되는 방식)은 쓰지 않는다. 스크립트 안에 이동·추출·후처리·
종료까지 전부 넣고, 결과만 받아 판정한다.

- L1: 작업 전체를 JS 파일 하나로 써서 `run.sh -f job.js` 1회 호출.
  내장 `open`/`read`도 1회 호출 완결형이다.
- L2: 이미 단일 .ps1 1회 실행 패턴이 원샷이다 (아래 호출 요점 참조).
- L3: 기존부터 1회 호출 원칙 (3단계 세션 규칙).
- 예외: 실패 코드가 발생한 경우만 체인 규칙대로 다음 시도/레인으로 넘어간다.
  원샷은 "첫 시도"의 형태를 정하는 것이고, 폴백 규칙(2단계)은 그대로다.
- L1 데몬은 웜 유지가 기본이다: 작업 전 `run.sh warm`으로 데몬+Chromium을
  띄워 두면 이후 호출은 웜 속도(실측 3.6~4.1초)로 떨어진다. 데몬 소스에는
  유휴 종료 타이머가 없어 설계상 stop/크래시/재부팅 전까지 상주한다
  (단, 원인 미상의 정지 1회 관찰 — 작업 전 status 확인 권장).

실측 (2026-11-21, HN 상위 3글 제목·URL, 원샷 스크립트):
콜드(데몬 정지→-f 1회) 18.1초 / 웜 3.6~4.1초 / `run.sh warm` 콜드 예열 14.2초.
기준선 (2026-11-20, 콜드 실패+재시도를 별도 호출로): 총 42.4초.

## 1단계 — 작업 분류 (진입점에서 1회만 판정)

| 분류 | 기준 | 진입 레인 |
|------|------|----------|
| A. 공개 페이지 읽기·확인 | 로그인 불필요, 공개 정보 | **L1** |
| B. 로그인 필요 | 세션이 있어야 내용이 보임 | **L2** |
| C. 봇 차단 예상 | Cloudflare 등 봇 방어가 강한 사이트 (나무위키 등 기확인) | **L2** (탐지되면 L3) |
| D. 사용자 크롬 보호 | L2가 사용자 크롬과 간섭하면 안 되는 작업 | **L1 → L3** |
| E. 결제·사용자 시청 | 결제, 사용자가 직접 봐야 하는 흐름 | **L4** (체인 제외) |

애매하면 A로 시작한다. 분류는 작업당 1회만 하고, 이후 전환은 실패 코드로만 한다.

## 2단계 — 실패 코드와 전환 규칙

작업 중 아래 신호를 만나면 즉시 해당 코드로 판정하고 표대로 움직인다.

| 코드 | 실패 신호 | 다음 동작 |
|------|----------|----------|
| F-IP | HTTP 403/429, "Too many requests", IP 차단 문구 | 같은 레인 재시도 **금지** → IP가 다른 레인으로 (L1→L2) |
| F-BOT | "Attention Required", 봇 판정·캡차 벽 | L2→L3. L3도 막히면 중단·보고 |
| F-AUTH | 로그인 벽, 세션 만료 | L2로. L2에도 세션 없으면 사용자에게 보고하고 중단 |
| F-EMPTY | 본문 추출 공백, 선택자 불일치 | 같은 레인에서 추출 방식을 바꿔 **1회만** 재시도 (예: 선택자 추출 → `innerText` 폴백) → 그래도 비면 다음 레인 |
| F-TIMEOUT | 레인 제한 시간 초과 (L1 호출 60초 등) | 다음 레인 |
| F-RENDER | 화면 확인이 필요한데 렌더 불가 | L2 또는 L4 |

공통 규칙:
- 레인당 재시도는 최대 1회, F-EMPTY 방식 변경 같은 "다른 시도"일 때만.
- **동일 실패 신호가 두 레인 연속이면 체인을 멈추고 보고한다** (무한 하강 금지).
- 전체 시간 예산은 **5분**. 초과가 예상되면 중간 보고하고 계속 여부를 확인한다.

## 3단계 — 세션·연속성 규칙

- 레인 간 세션은 공유되지 않는다. 로그인 상태가 필요한 작업은 한 레인에 고정한다.
- 중간 산출물(추출 텍스트, URL, 진행 상태)은 레인을 넘어 인계한다.
  다음 레인은 처음부터 다시 하지 말고 **실패 지점부터** 이어받는다.
- L3는 호출당 ~40초 고정 비용이다. L3로 내려갈 때는 남은 작업 전체를
  작업 파일 하나로 묶어 **1회 호출**로 끝내는 것을 원칙으로 한다.

## 레인별 호출 요점 (상세는 각 스킬 문서)

- **L1 UltraBrowse**: 원샷이 기본 — `run.sh -f script.js` 1회 호출로 완결한다.
  `run.sh open <url>` / `run.sh read <url>`도 1회 완결형. 호출당 하드 타임아웃
  60초. 데몬 콜드 첫 호출은 ~15초 걸릴 수 있으니 재시도하지 말고 기다린다.
  `-f` 경로는 콜드 소켓 레이스(ENOENT daemon.sock) 때만 래퍼 내부에서 1회
  자동 재시도한다 (2026-11-21). 작업 시작 전 `run.sh warm`으로 예열해 두면
  콜드 비용을 작업 시간 밖으로 뺄 수 있다.
- **L2 agent-browser (H255)**: `~/workspace/tailnet/pc-ssh.sh`로 접속해
  PowerShell `-EncodedCommand`(UTF-16LE base64)로 단일 .ps1 스크립트 1회 실행에
  전 과정을 묶는다. .ps1에 한글을 넣으면 인코딩이 깨지니 스크립트는 ASCII로 쓰고,
  refs(@eN)는 호출 간 유지되지 않으니 CSS 선택자/eval을 쓴다.
- **L3 ego-lite-h255**: `~/workspace/custom-skills/ego-lite-h255/run.sh <job.mjs> [timeout]`.
  결과는 출력의 STDERR 섹션에 온다. SSH에서 ego-browser를 직접 실행하면 EXIT=9로
  거부되니 반드시 run.sh(스케줄 작업 경유)를 쓴다.
- **L4 클라우드 브라우저**: 분류 E 전용. 체인으로 내려오지 않는다.

## 보고 포맷 (작업 종료 시 필수)

```
성공 레인: L2 (agent-browser)
총 시간: 22초
경유: L1 실패 (F-IP, 위키미디어 429) → L2 성공
```

- 성공 시: 성공 레인, 총 시간, 경유(실패 코드 포함)를 위 3줄로 남긴다.
- 실패로 끝난 경우: 전 레인의 실패 코드를 나열하고, 사용자 개입이 필요한
  지점만 명시한다.
- 경유가 없는 단일 레인 완결도 "경유: L1 단독 완결"로 명시한다.

```
[테스트 1] HN 상위 3글 제목·URL
성공 레인: L1 (UltraBrowse)
총 시간: 약 13초
경유: L1 단독 완결

[테스트 2] 위키백과 '크로미엄 (웹 브라우저)' 도입부
성공 레인: L1 (UltraBrowse)
총 시간: 약 27초
경유: L1 첫 시도 타임아웃 오류 → 재시도 로드 성공 → 선택자 추출 F-EMPTY → innerText 방식으로 완결
비고: 설계 기대(F-IP→L2)와 달리 위키미디어 429가 해제돼 F-IP 미발생.
      L2 하강 경로는 별도 실행으로 검증 (페이지·도입부 확보, 약 7초, innerText 필요).

[테스트 3] 나무위키 Chromium 도입부
성공 레인: L2 (agent-browser)
총 시간: 약 19초
경유: L1 실패 (F-IP, Cloudflare "Attention Required") → L2 성공 (L3 불필요)
```

실측에서 확인된 주의점:
- 위키백과 본문은 `.mw-parser-output > p` 선택자 추출이 L1·L2 모두 빈 값을
  반환하는 경우가 있다 — 처음부터 innerText 폴백을 기본으로 섞어 쓸 것.
- L1은 간헐적으로 하네스 타임아웃 오류가 날 수 있다 (테스트 2 첫 시도).
  실패 코드를 단정하기 전에 오류 내용을 확인할 것.
